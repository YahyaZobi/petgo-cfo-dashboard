## Key Decisions Made
- **Security: proceed as-is (user chose).** Publishable key ships in public HTML; every table is world read/write via allow-all RLS. Accepted for now; hardening (Supabase Auth + real RLS) is a flagged future task. New tables I created follow the same allow-all pattern deliberately.
- **Seed demo data into Supabase (user chose)** for non-employee modules — so Finance/Projects/Pipeline/Reports show realistic data. Employees is the exception (stays empty).
- **Architecture: Supabase = source of truth, localStorage = offline mirror.** Chosen because every render reads module-level arrays synchronously; making them async would mean rewriting all render code. Instead: async bootstrap fills in-memory arrays + localStorage mirror on load; each `save*Store()` also upserts to Supabase. Minimal-diff, keeps sync render code intact.
- **Dashboard KPIs/trends → new small tables (user chose "Recommended").** The schema has NO revenue/cash/EBITDA/monthly-financials source (invoices are vendor *payables*, not revenue), so those headline numbers can't be "aggregated from budgets/invoices" as the prompt assumed. Created dedicated financials tables seeded with current values instead of fabricating aggregations.
- **Follow prompt order (user chose)** over the "Finance-before-Dashboard" dependency fix — user accepted that some numbers stay near-zero until Finance is seeded (moot now, since financials tables are seeded).
