## Known Issues / Blockers

1. **Dashboard not wired to server** — The biggest gap. `fetchModule()` in the dashboard still uses MSAL Graph API calls. It needs a second path: when `http://localhost:8000` is reachable, call `/api/{module}` instead. This is the core dynamic architecture work.

2. **Microsoft 365 sign-in only works from Netlify** — Because the Azure redirect URI is `https://petgo-dashboard.netlify.app`. From `file://` or `localhost:8000`, the MSAL popup will still fail. Fix: add `http://localhost:8000` as a second redirect URI in Azure, then detect origin in code and set redirectUri dynamically.

3. **Server not connected to SharePoint yet** — `connectors/excel_graph.py` exists but config.json has all sources disabled with empty paths. Someone needs to configure it.

4. **Netlify redeploy on every change** — The user explicitly said they don't want this. Solution: run `server.py` locally (it serves the HTML too) and never use Netlify for day-to-day use; Netlify becomes an optional hosted fallback.

5. **`msalApp` reference in `loginMS()`** — The old code referenced `msalApp` (undefined); it was fixed to use `_msalInstance` via `_initMSAL()`. Double-check this on the Netlify deployment.

## Next Steps (priority order)

1. **Wire the dashboard to the local server** — The dashboard needs to detect if `http://localhost:8000` is running, and if so, call `/api/{module}` for data instead of localStorage. Add a `fetchFromServer(module)` function that: (a) tries `fetch('http://localhost:8000/api/'+module)`, (b) on success calls `_applyAPIData(module, data)`, (c) on failure falls back to localStorage. Hook this into the `navTo` override alongside the existing MSAL fetch path.

2. **Dynamic redirect URI for MSAL** — Detect origin at runtime:
   ```javascript
   redirectUri: window.location.origin.startsWith('http://localhost') 
     ? 'http://localhost:8000' 
     : 'https://petgo-dashboard.netlify.app'
   ```
   Also add `http://localhost:8000` to Azure app's redirect URIs.

3. **Settings UI — show server status** — Add a "Local Data Server" section above the Microsoft 365 card showing: green dot if `localhost:8000` is reachable, last sync time, link to API docs. This replaces the Microsoft sign-in as the primary data path when running locally.

4. **Wire Excel upload to main dashboard charts** — The upload pipeline processes files into `pendingData` but KPI cards and charts on the Dashboard tab never update. `renderExec()`, `renderPL()`, etc. need to check `pendingData` or the server cache.

5. **Deploy workflow** — Once the server is the primary data path, Netlify is only needed for sharing with remote users. Document: run `bash start.sh` for local use; push to Netlify only for remote access.
